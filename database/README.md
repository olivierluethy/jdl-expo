# database/

MySQL tooling and the SQL dumps of the TuneVote database. Two small scripts move
data in each direction — one reads a schema out of a live server, one pushes a
generated dump into one — and four `.sql` files hold the data itself.

> ⚠️ **Both scripts contain hardcoded database credentials in plain text**,
> including the password of a remote, publicly addressable MySQL server. These
> were deliberately left unchanged, because moving them would change which
> database each script talks to. See [`../SECURITY_NOTES.md`](../SECURITY_NOTES.md)
> before running anything here or sharing this repository.

## schema_inspection/

| Script | Purpose |
|---|---|
| `export_mysql_schema_to_sql.py` | Connect to MySQL, run `SHOW CREATE TABLE` for every table, write the result to one file |

Produces a schema-only snapshot — structure, no rows — which is what you want
for diffing environments or recreating an empty copy of the database. Its output
is `dumps/tunevote_schema_structure.sql`, and it **overwrites** that file on
every run.

The connection block currently points at a local `easycontactforms` database.
The previous remote host, password and database name are still present as
commented-out lines directly above the active ones.

## connections/

Reserved for shared connection helpers and configuration. Currently empty —
both scripts here open their own connection inline. If the credentials are ever
centralized, this is where that belongs.

## parsers/

| Script | Purpose |
|---|---|
| `import_sql_dump_into_mysql.py` | Stream a large SQL dump into MySQL, statement by statement |

Reads `dumps/tunevote_artists_and_videos_insert.sql` a line at a time rather than
loading it into memory, which matters because that file is over 40 MB. It treats
any line ending in a semicolon as the end of a statement — reliable for
machine-generated dumps, but not for arbitrary SQL, since a semicolon at the end
of a line inside a quoted string would split it incorrectly.

It runs with autocommit on, so there is **no surrounding transaction**: if it
fails partway through, the statements already executed stay applied.

## dumps/ — data, do not delete

| File | Size | Lines | Contents |
|---|---:|---:|---|
| `tunevote_artists_and_videos_insert.sql` | 42 MB | 113,296 | `INSERT IGNORE` into `artists` and `youtube_video_cache`, wrapped in a transaction. Generated by the two SQL exporters in `tunevote/scrapers/` |
| `youtube_video_cache_insert.sql` | 5.7 MB | 29,363 | A bare `INSERT INTO youtube_video_cache` dump — the original 29,364-row export |
| `tunevote_phpmyadmin_full_dump.sql` | 300 KB | 2,043 | A proper phpMyAdmin dump, schema **and** data, of an early TuneVote database |
| `tunevote_schema_structure.sql` | 16 KB | 339 | Schema only: 20 `CREATE TABLE` statements. Output of `export_mysql_schema_to_sql.py` |

### What is in them

`tunevote_schema_structure.sql` describes the full data model as it stands:
`artists`, `youtube_video_cache`, `users`, `sessions`, `session_participants`,
`session_invites`, `queue_items`, `votes`, `voting_rounds`, `playback_sync`,
`playback_history`, `session_song_listens`, `guest_users`, `shouts`,
`shout_likes`, `badges`, `user_badges`, `user_badge_progress` and the two
`knex_migrations` bookkeeping tables.

`tunevote_phpmyadmin_full_dump.sql` is older and narrower — nine tables, no
`artists` — and predates the artist work described in
[`../docs/project_history_en.md`](../docs/project_history_en.md).

The same `youtube_video_cache` payload exists twice: as
`youtube_video_cache_insert.sql`, and embedded in a string literal inside
`tunevote/processing/extract_unique_artists_from_dump.py`. Both were kept.

### Caution

- `tunevote_phpmyadmin_full_dump.sql` contains a real `users` table. It was not
  inspected for personal data or password hashes. Review it before this
  repository goes anywhere.
- Both scripts overwrite or import without prompting. Neither asks for
  confirmation, and neither takes a backup.

## Running

Paths are relative to the **repository root**:

```bash
python database/schema_inspection/export_mysql_schema_to_sql.py
python database/parsers/import_sql_dump_into_mysql.py
```
